1. 設計背景コラム（私見）：牌理以前と牌理以後のアプローチ変遷

※本節は厳密な麻雀歴史考証ではなく、本ツールの設計思想を整理するための開発者の設計メモ（私見）です。

1-1. 牌理以前：ゲームの構造と「不確実性の濃淡」

立直麻雀というゲームを構造面から眺めたとき、ひときわ強い特徴になっているのが「放銃一家包（ロンされた1人が点数を全額支払う仕組み）」と「フリテン」の組み合わせです。自分のアガリだけを追えばよいわけではなく、自分の河に捨てた牌がそのまま相手に対する防御の安全牌（現物）になり、同時に自分の待ちの制約にもなる――この仕組みによって、攻撃と守備が1枚の打牌の中で切り離せない攻守一体のゲーム性が生まれています。

そして卓上のプレイヤーが置かれているのは、全情報が見渡せる神視点ではなく一者視点です。自手・河・副露・ドラ表示牌のように確定した領域から、捨て牌順や手出しツモ切りといった推察の中間層を経て、他家手牌・山・王牌という深い霧の中へと連なる不確実性のグラデーションの中で、限られた思考資源を使って毎巡の決断を下し続ける構造になっています。

1-2. 牌理以後：計算アプローチの変遷と「翻訳の置き去り」

麻雀を数理・計算機で扱おうとする試みは、時代とともに大きく段階を経てきました。本ツールの設計にあたっては、その流れを次の3つの段階として捉えています。

  1. モンテカルロ探索 ➔ 牌譜統計と「次元の呪い」
    不完全情報の中で期待値を測る試みとして、未知の山・他家手牌を何度も仮定して回すモンテカルロ探索や、膨大な実戦牌譜から条件別の和了率・放銃率・局収支を割り出す統計アプローチが発展しました。しかし、巡目・点数状況・ドラ枚数・他家の仕掛け・河の濃淡といった条件が掛け合わさるほど局面空間は爆発的に膨れ上がり、細かな局面の文脈をすべて統計表に収め切ろうとすると「次元の呪い」に突き当たります。
  2. 深層強化学習AIの台頭 ➔ ブラックボックス化と「翻訳の置き去り」
    深層強化学習ベースの専門麻雀AIが登場し、人間のトップ層を凌駕する強さと、局面ごとの推奨打牌・悪手率といった評価値を提示できるようになりました。一方で、強さが飛躍的に高まった反面、その判断根拠は高次元の重みの中に畳み込まれたブラックボックスになりがちです。「なぜこの1打が良いのか」「人間の実戦感覚とどこでズレたのか」を人間が再現可能な言葉へ落とし込む翻訳のプロセスが置き去りになりやすいという課題が残ります。
  3. LLMによる言語化・対話の提案 ➔ 決定論的コア8割 × 確率的LLM2割の疎結合分業
    汎用LLMは麻雀の厳密な枚数計算や向聴数カウントをそのまま任せると容易に数え間違い（ハルシネーション）を起こしますが、与えられた確定指標をもとに方針の比較や読みの言語化・対話を行う適性を持っています。そこで本ツールは、136枚の物理保存則・全28役複合向聴数・受入・見かけ残り枚数・安全度といった「決定論的コア（8割）」をブラウザ内の純粋ロジックで厳密に算出し、言語化や方針比較といった「確率的LLM（2割）」へ疎結合に渡す分業構造を採っています。

設計の結論：強いAIの正解を当てさせる機械ではなく「道場」へ

本ツールが目指しているのは、最強AIの1択の正解を当てさせて採点する機械ではありません。確定指標（機械の「目」）と、人間やLLMの推論（方針・言語化の「頭脳」）を並べて比較し、必要なら同じ局面を別ツモで打ち直して確かめられるスパーリング環境（道場）を提供することです。

2. 人間思考 × AI思考の往復実験（スパーリング手法）

2-1. 専門麻雀AI（強化学習系）と汎用LLMの役割の違い

専門麻雀AI（強化学習系）

膨大な自己対局によって期待値・順位分布を最適化する「勝率の基準点」として極めて優秀です。一方で、判断の背後にある思考手順を人間向けに噛み砕いて対話する役割は本来領域ではありません。

汎用LLM（本ツール連携・プロンプト併用）

単体では麻雀の厳密計算が苦手ですが、本ツールの静的解析（確定事実）を土台に与えることで、「速度・打点・守備のトレードオフを言語化する壁打ち相手」として機能します。

2-2. 人間×AI思考往復の5ステップ・テンプレート

外部LLMやローカルLLMを練習の壁打ち相手として使う際は、いきなり「何を切るべき？」と聞くのではなく、次の5ステップで人間とAIの思考を往復させると学習密度が大きく上がります。

  1. 局面の提示
    検討したい1局面をテキスト形式（Spec v1.2）や本ツールの盤面・静的解析データとして整理し、確定している公開情報だけを明示します。
  2. 人間の実戦感覚
    先に人間側が「この局面で自分は何を切りたいか」「どの手役や押し引きを意識したか」「誰をどの程度警戒しているか」を短く書き出します。
  3. 機械の「目」で見る
    本ツールの静的解析パネル（全28役複合向聴数・ΔS・受入・見かけ残り枚数・見え切り警告・守備安全度）で、数え漏れや前提の見落としを確定させます。
  4. AIの「頭脳」と比較
    本ツールの外部LLM連携（Mode 2 / セカンドオピニオン FULL）や、次節の「1局面解説プロンプト」を使って、方針別の選択肢比較や他家読み（opponentRead / reason）を引き出し、自分の思考と突き合わせます。
  5. 人間へのフィードバック
    AIの言葉を鵜呑みにせず、「自分の見落としていた判断軸は何か」「逆にAIが軽視していた場況や点況は何か」を1〜2行で言語化し、必要なら 🎲 IF別ツモ FULL で別展開を打ち直して検証します。

2-3. 「1局面主軸」と「転換点抽出」の切り分け

1局の最初から最後まで、あるいは半荘全体の全巡目をAIに一括で詳細解説させようとすると、コンテキストの情報量が肥大化して後半の精度が落ちたり、途中の手出し・ツモ切りが省略されたログの限界から無理な後知恵推測が混ざりやすくなります。

そのため実務では、① 本当に迷った「1局面」を深掘りする（1局面主軸）ことと、② 1局・半荘全体を通す場合は「分岐が生じた2〜3か所の転換点だけを抽出する（転換点抽出）」ことに役割を切り分ける運用を推奨します。

3. 実務プロンプト集（外部AI・ローカルLLM連携用）

お持ちの外部AIチャット（ChatGPT / Claude / Gemini 等）やローカルLLMへそのまま貼り付けて使える実務プロンプトです。各ブロック右上のボタンからワンクリックでコピーできます。

3-1. 単発OCR・文字起こし補助プロンプト（画像・メモ ➔ Spec v1.2 変換）

盤面のスクリーンショットや手書きメモを、本ツールでそのまま読み込める 1 行テキスト形式（Core Protocol Spec v1.2 粗結合文字列）へ変換するためのプロンプトです。

読み込み手順：AIが出力した1行テキストをコピーし、アプリ上部の 📂 牌譜・保存（FREE版では 📂 局面をひらく） ➔ 📋 コード貼付で読込 ➔ 📥 盤面に読み込む を押します。

つまずきやすい2大ポイント（重要注意）

  1. 1局＝必ず1行（パイプ | 区切り）：途中で改行（\n）が入ると、本ツールは別々の局として分割して解釈します。出力が複数行に折り返されていた場合は1行に繋ぎ直してください。
  2. ツモ切り . やリーチ * は直前の1牌のみに帰属：たとえば 12m. は「1m が手出し、2m のみツモ切り」という意味になり、1.2m のような途中挿入は構文エラーになります。記号を付けたい牌は 1m.2m や 1m*2m のように、1牌単位でスート文字を付けて記述してください。
プロンプト 3-1：単発OCR・文字起こし補助（Spec v1.2 変換） 
あなたは麻雀の盤面画像またはテキストメモを、以下のプレーンテキスト形式（Core Protocol Spec v1.2 粗結合文字列）へ正確に文字起こしするアシスタントです。

【厳守ルール】
1. 出力は必ず「1局＝1行」とし、各項目は改行せずパイプ（ | ）で繋ぐこと（改行すると別局として解釈されるため厳禁）。
2. 画像やメモから「100%確実に読み取れる牌」だけを記載すること。
3. 伏せられている他家の手牌、読み取れない牌、不鮮明な牌は絶対に推測で補完せず、`?` と記載するか、該当項目を省略すること（ハルシネーション厳禁）。
4. 牌の表記は MPSZ形式（萬子:1m-9m, 筒子:1p-9p, 索子:1s-9s, 東:1z, 南:2z, 西:3z, 北:4z, 白:5z, 發:6z, 中:7z、赤5は 0m/0p/0s）を使うこと。
5. 河（捨て牌）の修飾記号（リーチ宣言牌 `*`、ツモ切り `.`）はスート文字の直後にある1牌のみに帰属する。連続する同スート牌に記号を付ける場合は `1m.2m` や `1m*2m` のように1牌ごとにスート文字を書くこと（`1.2m` は構文エラー）。ツモ切り判別不能な牌には `.` を付けないこと。

【出力フォーマット（1行サンプル）】
round: E1 | honba: 0 | kyotaku: 0 | dora: 5p | scores: 25000,25000,25000,25000 | hand0: 123m456p789s1155z | river0: 9s1z.2z | river1: 1m9p7z* | river2: 3z4z | river3: 8m2p

※ 0=自家, 1=下家, 2=対面, 3=上家。他家手牌（hand1〜hand3）が伏せられている場合は項目を省略するか `hand1: ?????????????` とすること。
上記の1行フォーマットのみをコードブロックで出力し、戦術的な解説や推測は一切書かないでください。

3-2. 1局面解説プロンプト（後知恵抑止・不確定断定回避）

1局面の盤面情報と静的解析の数値をもとに、後知恵や不確定情報の断定を抑えながら、方針別の比較と意識すべき判断軸を整理してもらうためのプロンプトです。

プロンプト 3-2：1局面解説（後知恵抑止・不確定断定回避） 
あなたは麻雀の「一視点の思考整理アシスタント」です。提示された1局面の盤面情報（視点プレイヤーから観測可能な公開情報と静的解析指標）のみに基づき、この局面の構造と選択肢を解説してください。

【厳守制約】
1. 後知恵バイアスの禁止：結果や未来のツモを前提にした評価を一切行わないこと。
2. 不確定情報の断定禁止：伏せられている他家の手牌や山に残っている牌を「持っているはず」「山にいる」と断定しないこと。必ず「河や副露から推察される可能性」「見かけ上の残り枚数」として表現すること。
3. 正解の押し付け禁止：1つの打牌を絶対の正解として断定せず、方針の違い（速度・打点・守備）による選択肢の比較として提示すること。

【出力構成】
1. 状況の整理（確定事実）：巡目、点棒状況、ドラ、自手の現在向聴数と狙える手役の方向性。
2. 他家の河・場況の読み（仮説）：各家の手出し・ツモ切り・副露から読み取れる進行度と警戒すべき色・牌。
3. 主な選択肢の比較（2〜3案）：
   - 候補A（速度・受け入れ重視）：メリットとリスク
   - 候補B（打点・手役重視 または 守備・スリム化重視）：メリットとリスク
4. この局面で意識すべき判断軸（1〜2点）：実戦で同様の局面に出会った際の思考の焦点。

4. データ4形式とオープン規格（Core Protocol Spec v1.2 概要）

本ツールは特定サーバーや独自バイナリに閉じ込めないため、用途に応じた4つのオープンなデータ形式を使い分けています。

データ形式 表記・識別子 主な用途と特徴
① 粗結合文字列 Spec v1.2
（1局＝1行 | 区切り）		 人間が読んで直接編集しやすく、外部AIチャットとの入出力にも強いプレーンテキスト形式。改行（\n）で複数局を並べた .txt バッチ読込（FULL）にも対応します。
② 単局シード #ST317-... URLハッシュに1局分の盤面・設定を圧縮格納する共有形式。SNSやメモでURLが途中で切れる事故を防ぐため 2,000字ガード を備えています。
③ 何切る出題シード #QZ1-... 1打回答式の何切る問題を出題するための共有形式。回答するまでヒント・正解・解説をロックするネタバレ防止仕様を備えます（作成はFULL、回答はFREE/FULL共通）。
④ 視点マスク済みJSON JSONファイル / ペイロード FULL版のローカル保存庫バックアップ（エクスポート／インポート）および外部LLM連携時の構造化ペイロードとして使用します。

プロトコル設計の2つの基本原則

  • 物理保存則（136枚上限・行番号エラー検出）：同種牌の4枚超過や136枚を超える矛盾した入力を検証し、複数局バッチ読込時も該当行番号を明示してエラー検出します。
  • 透視遮断と確定情報の保持（Round-Trip 防護）：非公開の手牌や未判別のツモ切り（unknown）を勝手に捏造せず保持し、書き出し ➔ 再読み込み（Round-Trip）を繰り返しても「確定していた情報」と「不明だった情報」の境界が壊れない設計です。

5. データの4分類・権利帰属と利用マナー

本ツールはオープンテキストの純粋な「受け皿」として動作するため、取り扱う局面・牌譜データの由来と公開可否は、利用者自身が以下の4分類（アプリ内 ❓ 解説 規約の正本表記と統一）に沿って自己管理します。

区分（アプリ内正本表記） 想定されるデータ例 利用・公開の目安
① 自作・個人練習 ご自身で作成した何切る問題・ランダム配牌・手組練習データ。 制限なし（個人利用・共有・公開いずれも可）。
② 権利者公開・許諾済 権利者本人が公式公開しているデータ、または利用・共有許諾済の牌譜・局面。 許諾範囲内で可（各権利者が示す条件・クレジット表記を遵守）。
③ 私的メモ・研究用 個人学習・検討目的の私的メモや研究データ。 私的利用のみ可／無断での公開・再配布は NG。
④ その他第三者由来データ オンライン麻雀の実戦牌譜・書籍・動画・有料教材等の第三者由来データ。 私的練習のみ可（提供元の規約・権利条件を確認）／無断公開・転載・出題リンク公開は NG。

運用上の重要原則（アプリ内規約 全8項目対応）

  • 単発手作業と自動抽出の境界：本アプリの利用範囲は、1牌譜単位の手動入力・テキスト貼付および単発のOCR補助による検討・学習に限定されます。URL指定による自動取得、配信画面の常時キャプチャ、複数試合の一括収集（スクレイピング・自動巡回）には一切非対応であり、これらを目的とした利用を禁止します。
  • エアギャップ原則：アプリ本体はオープンテキスト形式（Spec v1.2 / ST317 / QZ1）の純粋な「受け皿」に徹し、他社サービスからの自動抽出機能や専用コンバータを一切内蔵せず、外部サービスから独立して動作します。
  • 掲載元コンテキストによる真正性判断（なりすまし免責）：プロトコル文字列や共有コード自体に暗号署名や発行者認証はありません。公式性や許諾の有無は文字列そのものではなく、「権利者本人の公式概要欄・公式アカウント等に掲載されているか」という掲載元コンテキストで判断してください。なりすまし・改変された文字列の信頼性や紛争について開発元は責任を負いません。
  • 他社データ無断公開の禁止：第三者の対局データ、著作権物、各サービスの利用規約で転載・再配布が禁じられたデータの無断公開・再配布を行わないでください。共有リンクやテキスト出力の公開適法性は利用者自身の責任で確認するものとします。
  • AI生成牌譜の著作権と「研究パッケージ」の考え方：内蔵AIやLLMの対局・検討から生成された単なる牌の並び（データ配列）そのものを独占的に囲い込むのではなく、人間が選んだ局面・設問・解説・構成といった創作的な編集やコメントを伴う「研究パッケージ」として価値を扱う考え方を推奨しています。
  • 外部LLM送信同意とAPIキー保存範囲：外部・ローカルLLM連携はFULL版における任意のオプトイン機能であり、初回利用時に送信同意を確認します。送信プロンプト・静止画・APIキーは開発元サーバーへ一切収集されず、利用者ブラウザ内から指定先への直接通信で完結します（APIキーは既定でメモリ保持のみ／明示オプトイン時のみ端末の localStorage に保存、ログ・JSON出力には非混入）。
